# Разбор проблем исходного проекта и что исправлено

Источники: код `kb/*`, `.env`, журнал `data/logs/requests.sqlite3` (реальные запросы 29–30.09), индекс `data/index`, `faq.csv`.

## A. Почему LLM «не может нормально отвечать»

| # | Проблема | Доказательство | Исправление |
|---|---|---|---|
| 1 | qwen3:4b вызывался через OpenAI-совместимый `/v1/chat/completions` в режиме «рассуждений» (thinking), без `num_ctx`/`num_predict`/`keep_alive` | В журнале ответы идут 56–122 с, а два запроса (30.09 16:07 и 16:16) — ровно по 180 с и `llm_unavailable` при retrieval_score 0.90 | Нативный `/api/chat`: `think=false`, JSON-схема в `format`, `num_predict`, `keep_alive`, прогрев модели при старте, быстрый отказ при недоступном сервере (connect-timeout 5 с) |
| 2 | Решение «подходит ответ или нет» принимал порог косинуса | `KB_MIN_SIMILARITY` 0.86 (в `.env.example` 0.80). На вашем индексе средний cosine между случайными вопросами **0.80**, т.е. 0.80 — это шум, а 0.86 режет перефразировки | Порога-судьи нет. Кандидаты (top-5, ≥0.82) показываются модели, она выбирает номер или 0 |
| 3 | `ranking.select()` выбрасывал кандидатов ручными эвристиками: требовал общие слова (между ru/kk/en их нет), фильтр «определений», проверка аббревиатур | Журнал: «Кто такой эдвайзер?» → `no_relevant_source` трижды, «Who is Student?» → то же | Модуль удалён, межъязыковый поиск работает на эмбеддингах |
| 4 | Жёсткая привязка к датасету: при найденном кандидате `basis` обязан быть `retrieved`, иначе ошибка; отвергнуть кандидата и ответить самой модель не могла | `generation.py`: `if matched and basis!='retrieved': raise` | `match=0` — штатный путь: модель отвечает сама |
| 5 | `can_answer=false` → «Обратитесь в деканат» на любой вопрос, в котором 4B-модель не уверена | «How to take attendence?» (score 0.83) → «Please contact the Dean's Office» | Модель всегда отвечает; про неизвестные факты SDU честно говорит и называет, куда обратиться |
| 6 | Строгая схема: `set(parsed) == {'can_answer','basis','explanation'}` | Малая модель регулярно нарушает → `invalid_model_output` → fallback | Схема из 2 полей + декодирование по JSON-схеме, терпимый парсер, 1 повтор с подсказкой, проверка языка ответа |
| 7 | Язык по умолчанию `ru` в API | Английский вопрос → русский ответ (журнал: «How to take attendence?» с `language=ru`) | `language=auto` (определение по алфавиту), явные ru/kk/en сохранены |
| 8 | `ChatClient` требовал непустой `LLM_API_KEY` даже для локальной Ollama; `finish_reason != 'stop'` считался ошибкой | `generation.py: ChatClient.__init__` | Ключ нужен только для openai/gemini |
| 9 | Второй одновременный запрос получал мгновенный 503 `service_busy` (неблокирующий Lock) | `api.py` | Очередь с ожиданием (`KB_QUEUE_TIMEOUT_SECONDS`), параллелизм настраивается |
| 10 | Любая ошибка LLM → «сервис недоступен», даже когда в базе есть точный ответ | — | Деградация: при сходстве ≥0.90 отдаётся ответ базы |

## B. Инфраструктура и согласованность

* **Postgres + pgvector в Docker ради 941 вектора** — лишняя точка отказа (в README: «Docker Engine недоступен»). Заменено индексом в памяти (`kb/index.py`), готовый индекс лежит в `data/index`.
* **README противоречил коду**: e5-small/384 vs e5-base/768 (и в docstring `embedding.py`), 735 vs 941 пар, OpenAI/Gemini vs Ollama, пути `C:\Users\tolai\...`; файл `requiremets.txt` (опечатка) и три requirements-файла. README переписан, requirements — один.
* **Длинный вопрос** → `ValueError: exceeds token limit` → 503. Теперь текст обрезается моделью эмбеддингов.
* **Падение поиска** валило весь запрос → теперь ответ без базы + `reason=retrieval_unavailable` и запись в лог.
* **Модерация**: промпт утверждал «Profanity alone is not a reason to block», хотя по требованиям нужен фильтр мата kk/ru/en; каждый пост шёл через 4B-LLM. Добавлен детерминированный фильтр (расширяемый файл шаблонов; ловит «х у й», «xуй», «хууууй»; проверено, что не режет «Страхуйте», «употреблять» и т.п.). При недоступной LLM — `review`, а не `allow`.
* **Гигиена архива**: в zip были `.env`, `__pycache__`, `requests.sqlite3` с реальными вопросами студентов. В новом архиве их нет; `.env` создан из `.env.example` без ключей.

## C. Данные (сам не менял — это решение команды)

* 668 из 941 записей — статус `needs_review` (не проверены); 56 ответов короче 15 символов («Да», «Жоқ») — без вопроса почти бесполезны.
* 4 повтора вопросов; 4 русских вопроса с казахским ответом.
* Есть быстро устаревающие факты (имя ректора, «F block») — нужен владелец и дата проверки.
* `config/university_context.txt` почти пуст: это лучшее место для проверенных фактов SDU.

## D. Чего это исправление НЕ делает

* Не проверялось на реальных qwen3:4b и E5: в среде, где собирался архив, нет доступа к Ollama и Hugging Face. Проверено: 56 тестов, сквозной прогон по реальным сокетам с имитацией Ollama, настоящий индекс. Качество ответов 4B-модели нужно оценить на ваших вопросах.
* Нет интеграции с живым форумом (лайки) — источник пока FAQ-таблица.
